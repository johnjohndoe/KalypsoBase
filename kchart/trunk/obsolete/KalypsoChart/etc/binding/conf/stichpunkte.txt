Beispiel für Konfiguration:







Das wird für die Konfiguration benötigt:

	BaseConfiguration
	Dataset-Liste: wird vom Sysadmin zusammengestellt und beschreibt die Datenquellen 
	Layer-Liste:
				vorkonfigurierte Diagramme; verweist auf Datasets sowie 1 oder 2 Spalten, die für ein Diagramm 
				verwendet werden sollen
(Anm: zu klären: Sollen alle denkbaren Kombinationen von Diagrammen ermöglicht werden, oder nur solche, die 
	paarweise mindestens eine gemeinsame Spalte haben? Nur in letzterem Fall entspricht ein Diagramm genau einer Tabelle;
	sonst müssten evtl. mehrere Tabellen zurückgeben werden - oder eine große, deren Zusammenhang nicht aus
	der Struktur ersichtlich ist; weitere möglichkeit: "Verschachtelte Tabellen" - dadurch würde beispielsweise
	eine Observation-Collection direkt als eine Tabelle zurückgegeben werden können. Das halte ich nicht für klug, weil
	so die Kontrolle über die dargestellten Daten verloren geht.
	) 
	  
	Style-Liste:	
(Anm.: Anders als beim WMS können Styles auf jedes Diagramm angewandt werden; allerdings werden evtl. nicht 
	alle Style-Definitionen im Diagramm berücksichtigt. Ein BarChart hat beispielsweise nicht per se Datenpunkte, etc.)
						


Operationen für Webservice:

	getCapabilities: Rückgabe der vorhandenen Layer / Datasets / Charts
O		VERSION=0.0.1
M		SERVICE=WDS
M		REQUEST=GetCapabilities
O		FORMAT=MIME_type (text/xml)
O		UPDATESEQUENCE)=string




	
(Anm: describeChart wird wohl nicht benötigt, weil das in der GetCapabilities mit übertragen wird)	
	describeChart: 	Beschreibung der Inhalte eines Layers
		layers:		Komma-getrennte Liste von Layern, deren Beschreibung zurückgeben werden soll;
					referenziert wird
					
	
(Anm: Es stellt sich die Frage, ob man die Unterscheidung zwischen Tabelle und Diagramm auf 2 Operationen 
	verteilen soll oder auf eine Operation, bei der ein Parameter als Switch dient. Im letzen Fall werden
	für die unterschiedlichen Rückgabetypen nur bestimmte Parameter ausgwertet - daher halte ich diese Vorgehen
	für nicht ideal weil zu unübersichtlich; 
	Thorsten sagt, er würde das gerne auf 2 Operationen verteilen - richtig so!
	)
	
	getDiagram		Gibt Grafik  zurück
		imgtype 	(nur bei IMAGE) Typ der Grafikausgabe: PNG; JPEG; GIF
		width		(nur bei IMAGE) Breite der Ausgabegrafik
		height		(nur bei IMAGE) Höhe der Ausgabegrafik
		name		Name eines vordefinierten Datensatzes
		(Kennzeichen) 
	#	style		Komma-getrennte Liste von Styles, die auf die Layer angewendet werden
		layer		alle darzustellenden Layer in einer bestimmten Reihenfolge; bezieht sich auf die Layer, 
					die zum per title angesprochenen Diagramm gehören; hier können nur die Reihenfolge
					der Layer und das auslassen eines Layers durch Nicht-nennung bestimmt werden - der Inhalt
					an sich ist bereits vorgegeben
					
	
	getHTMLTable:	Gibt HTML-Tabelle zurück
	
	
	
	Width: Breite der Ausgabegrafik
	Height: Höhe der Ausgabegrafik
	Type:	Typ der Ausgabe (JPEG, PNG, GIF bei Grafik, HMTLTable für Tabelle)


	Layer (nur für Grafikausgabe):
		URL: Pfad zu einer Observation; SOS-String oder Dateiname
		Column:	1 oder 2 Spalten, die verwendet werden sollen
			ColumnID: Id der Spalte aus ResultDefinition
			AxisId:  Id der Achse, auf die die Spalte abgebildet wird
		Title:	Name des Layers, über den die GetDiagramm-Operation auf ein Layer verweist
		Description: optionale Beschreibung
		
	Axis (nur für Grafikausgabe):
		Position: LEFT, RIGHT, TOP, BOTTOM
		Direction:	
		minVal: kleinster darzustellender Wert; reeller, integer, String oder date-Wert
		maxVal: größter darzustellender Wert
		Type:	
			DATE für Datumachse
			REAL:	Reelle Werte
			INT:	Integer Werte
			STRING:	Diskrete String-Werte
